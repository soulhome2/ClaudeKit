# ClaudeKit — общий набор Claude Code для проектов ITV

Скиллы, проверки и порядок работы с ревью, вынесенные из проекта **Incident Manager (IM)** и обобщённые для остальных проектов: LPR, Retail и следующих. IM остаётся оригиналом и эталоном: набор его не меняет и к нему не применяется.

## Что внутри

```
ClaudeKit/
├── VERSION, CHANGELOG.md
├── apply.py                    — перенести набор в проект, обновить, проверить расхождения
├── template/
│   ├── shared/                 — общие файлы: при update перезаписываются в проектах
│   │   ├── dot-claude/skills/__P__-review/SKILL.md, templates.md
│   │   ├── dot-claude/skills/__P__-fix/SKILL.md
│   │   ├── dot-claude/evals/run_triggers.py
│   │   └── tools/kit/          — check_links.py, check_ids.py, check_page.py
│   └── seed/                   — заготовки: создаются один раз, дальше принадлежат проекту
│       ├── CLAUDE.md, .gitignore, reviews/README.md
│       ├── dot-claude/settings.json, dot-claude/evals/triggers.md
│       └── dot-claude/skills/__P__-review/checklist.md
├── modules/
│   └── consilium/              — консилиум из нескольких агентов (по желанию)
└── projects/                   — пресеты: kit.json, чек-лист и evals, подготовленные для проекта
    ├── LPR/
    └── Retail/
```

`__P__` в путях — префикс проекта (`lpr`, `retail`), `{{ключ}}` в тексте — значение из `.claude/kit.json` проекта. Папка `dot-claude` при переносе становится `.claude`: удалённые инструменты Claude не могут писать в папки `.claude`, поэтому набор хранит их под другим именем, а `apply.py` переименовывает.

**Пресет** (`projects/<папка проекта>/`) — проектные заготовки, подготовленные до подключения: `init` берёт из него `kit.json`, чек-лист и запросы evals вместо общих заготовок. После `init` хозяин этих файлов — проект; пресет остаётся записью начальной настройки и больше не применяется.

**Правило одно:** общее правится здесь, проектное — в проекте. Проектное — это то, что знает о предметной области: CLAUDE.md (источник истины, проверки, договорённости), чек-лист ролей, набор запросов для evals, `kit.json`.

## Что взято из IM и как обобщено

| В IM | В наборе | Что поменялось |
|---|---|---|
| `CLAUDE.md`: источник истины, сгенерированные файлы, «что поменял → что проверить», договорённости | заготовка `CLAUDE.md` | те же разделы; скиллы ссылаются на них по названию, поэтому сами скиллы общие |
| `im-review` + `checklist.md` + `templates.md` | `<p>-review` | порядок и формат — общие; роли и пункты — в проектном `checklist.md`; `RULE` → `REQ` (требование ТЗ) |
| `im-fix` | `<p>-fix` | без машины состояний и мутаций; «где причина» — по префиксу пункта |
| `.claude/evals/` (30 запросов, precision / recall) | `run_triggers.py` общий, `triggers.md` проектный | имена скиллов берутся из `kit.json` |
| `.claude/workflows/verification-audit.js` + `prompts/` | модуль `consilium` | число аналитиков — параметр, вопрос — в проектном промпте |
| `.claude/settings.json` (allow / ask / deny) | заготовка | те же запреты, разрешены проверки набора |
| `reviews/README.md`: циклы, сквозные номера, важность | заготовка | без истории IM |
| `tools/check_links.py` | `tools/kit/check_links.py` | написан заново, без зависимостей |
| — | `check_ids.py`, `check_page.py` | новое: трассировка идентификаторов требований и запуск прототипа — то, что у проектов на стадии ТЗ проверяется автоматически |

**Не перенесено** — специфика IM, нужная только проектам с машиной состояний: `im-fsm` (формальная проверка автомата), мутации машины и кода, модель Quint, самопроверка прототипа, CI. Когда у проекта появится своя машина или тесты — брать из IM как образец и, если повторится во втором проекте, выносить сюда модулем.

## Как пользоваться

Команды — из папки `Repos` (на Windows `python` или `py`, на Linux `python3`).

**Подключить LPR и Retail (один раз, на вашем компьютере):** CLAUDE.md, README, `reviews/`, `tools/kit/` уже лежат в проектах; папку `.claude` с настройками из пресетов создаёт команда

```bash
cd Repos
python ClaudeKit/apply.py init LPR
python ClaudeKit/apply.py init Retail
python ClaudeKit/apply.py check LPR Retail      # «разошлось 0» у обоих
```

**Новый проект:**

```bash
python ClaudeKit/apply.py init SafeCity --prefix sc --name SafeCity --title "SafeCity — …" --repo https://github.com/soulhome2/SafeCity
```

Затем в проекте заполнить заготовки: `CLAUDE.md` (пометки TODO), `checklist.md` по ролям, `kit.json` → `checks` (идентификаторы требований, страницы прототипа), `review_scope` (о чём проект — попадает в description скилла и влияет на то, когда скилл вызывается), `triggers.md`. Проверить: `python ClaudeKit/apply.py check SafeCity`.

**Обновить проекты после правки набора:**

1. Поправить файл в `template/shared/` (или модуле; `.claude` здесь — папка `dot-claude`), поднять `VERSION`, записать в `CHANGELOG.md`.
2. `python ClaudeKit/apply.py check LPR Retail` — какие общие файлы отличаются. Причин три: новая версия набора, поменялись параметры в `kit.json` (например, `review_scope`) или кто-то правил общий файл прямо в проекте. В последнем случае посмотреть `git diff` в проекте и сначала перенести правку сюда, иначе update её сотрёт.
3. `python ClaudeKit/apply.py update LPR Retail`, в каждом проекте — `git diff`, коммит «ClaudeKit <версия>».
4. Менялись description скиллов — прогнать evals: `python .claude/evals/run_triggers.py` в проекте.

**Улучшение, найденное в проекте:** новый пункт чек-листа — в проектный `checklist.md`. Если он полезен всем — в заготовку `template/seed/.../checklist.md` (новые проекты получат его сразу, старым — перенести руками). Улучшение порядка работы скилла — сразу в `template/shared/`.

**Подключить консилиум:** `python ClaudeKit/apply.py init LPR --with consilium` (kit.json уже есть — добавится модуль), затем заполнить `prompts/consilium.md`.

## Где хранится и почему так

- **Отдельная папка `Repos/ClaudeKit` со своим git-репозиторием** (рекомендую `soulhome2/ClaudeKit`): история изменений набора, версия, второй человек получает его через `git pull`.
- **В каждом проекте — копия**, а не ссылка: скиллы Claude Code читает из `.claude/skills/` репозитория, ссылки и хардлинки ломаются на Windows, в Яндекс Диске и в облачных сессиях Claude, а копия едет вместе с проектом в git. Расхождение копий ловит `apply.py check`.
- **Версия у проекта** — `kit_version` в `.claude/kit.json`; в шапке каждого общего файла написано, что он из набора и где его править.

Когда набор устоится, его можно оформить как плагин Claude Code из этого же репозитория — тогда общие скиллы ставятся один раз, а в проектах остаются только `CLAUDE.md`, `checklist.md` и `kit.json`. Сейчас копирование проще и прозрачнее.
